# PPT Layout Video Pipeline

This skill treats the Guizang PPT layout system as the visual source of truth.
Remotion owns the timeline, audio, BGM ducking, codecs, final render, and the
frame-driven DOM animation layer. The slide composition itself remains the PPT
HTML section, not a separate Remotion remake.

## Architecture

```text
screenshots or storyboard
  -> public/ppt/index.html
  -> src/ppt-template.css extracted from the PPT template
  -> src/promo-data.ts with pptScenes[].html
  -> src/audio-config.ts with narration-sized scenes and beat timelines
  -> motionUnits with data-motion-id on visible PPT DOM and text spans
  -> Remotion renders the PPT DOM directly and drives [data-anim] elements
  -> optional Playwright PNG slides in public/slides/*.png for QA/fallback
```

This keeps the video layout consistent with the PPT skill without rewriting every
PPT layout as a separate Remotion component. The older rendered-PNG path still
exists as `--render-mode slides`, but `ppt-dom` is the default because it allows
Remotion `useCurrentFrame`, `spring`, and `interpolate` to act inside the PPT DOM.

## Compatibility Contract

Full compatibility means:

- Style A layouts `A01-A10` map to `extra/guizang-ppt-skill/references/layouts.md`.
- Swiss layouts `S01-S22` map to `extra/guizang-ppt-skill/references/swiss-layout-lock.md`.
- `SWISS-COVER-ASCII` and `SWISS-CLOSING-ASCII` are the explicit Swiss cover/closing variants allowed by the PPT skill.
- `S08_MAP` maps to the registered `S08 + Swiss Map Component` extension.
- Experimental `P23/P24` are supported only when the storyboard provides raw `sectionHtml`.

See `references/ppt-layout-manifest.json` for the compatibility list.

## Native Defaults vs Raw Sections

The bootstrap script can generate a polished default deck from screenshots:

- `--layout-style editorial` generates `A01`, alternating `A04/A10`, and `A07`.
- `--layout-style swiss` generates `SWISS-COVER-ASCII`, repeated `S22`, and `SWISS-CLOSING-ASCII`.

For any other PPT layout, pass a storyboard scene with `sectionHtml`. The section
is inserted into the appropriate PPT template verbatim, written into
`pptScenes[].html`, and rendered by Remotion with the extracted PPT CSS. This is
the path that guarantees compatibility with every registered PPT layout, because
the original PPT HTML and CSS still own layout geometry.

`public/slides/*.png` is still generated by default as a visual QA/fallback asset.
It is no longer the primary video surface unless `--render-mode slides` is used.

## Storyboard Shape

```json
{
  "style": "swiss",
  "title": "Product Trailer",
  "scenes": [
    {
      "id": "cover",
      "layoutId": "SWISS-COVER-ASCII",
      "durationInFrames": 120,
      "transition": "fade",
      "sectionHtml": "<section class=\"slide accent\" data-layout=\"SWISS-COVER-ASCII\" data-scene-id=\"cover\">...</section>",
      "voiceover": "Opening narration.",
      "beats": [
        {"id": "cover-hook", "text": "Opening narration.", "target": "title", "motion": "title-reveal"}
      ]
    }
  ]
}
```

Recommended scene fields:

- `id`: stable ASCII identifier; used in rendered slide filenames.
- `layoutId`: `A01-A10`, `S01-S22`, `S08_MAP`, or an explicitly allowed experimental ID.
- `durationInFrames`: Remotion scene duration at 30 fps.
- `transition`: `fade`, `push`, or `cut`.
- `sectionHtml`: full PPT `<section class="slide ...">` block. Use this for full layout fidelity.
- `voiceover`: narration text consumed by `generate_voiceover_edge.py`.
- `beats`: optional narration beat hints. Each beat can choose a `target` such as `title`, `body`, `image`, `cards`, `diagram`, `kpi`, `bars`, or `line`.

Copy fields should come from the project article, README, product brief, or a
handwritten storyboard. If a source text is available, pass it with
`--brief-file <path>` so the default voiceover scaffold is grounded in the same
content instead of screenshot filenames.

If `beats` are omitted, the bootstrap script splits the narration into clauses
and assigns each clause to a layout-aware default motion plan. After TTS runs,
`generate_voiceover_edge.py` reallocates those beats against the measured audio
duration and writes `public/audio/motion-timeline.json`. The final beat always
ends at the scene boundary, which prevents the common failure where narration
continues over a static slide.

The bootstrap script also compiles each PPT section into `motionUnits`. It adds
`data-motion-id` to visible leaves such as images, cards, KPIs, bars, rules, SVG
shapes, and selected containers. Text nodes are wrapped into spans according to
`--motion-detail`:

- `normal`: phrase and leaf-node units.
- `fine`: denser phrase units.
- `glyph`: title and short text are split per character.
- `max`: all eligible text is split per character.

After TTS, every `motionUnit` is reallocated into a measured beat. Empty beats
borrow a few units from the densest bucket so no narration segment is visually
dead.

When using `sectionHtml`, include:

- `data-layout` or `data-layout-id`
- `data-scene-id`
- `data-title`

These attributes make the rendered slide manifest precise.

## Commands

Default editorial deck:

```bash
python scripts/bootstrap_promo_project.py \
  --workspace <output-dir> \
  --screenshots <screenshot-dir> \
  --project-name "Acme" \
  --tagline "Close work faster"
```

Swiss deck:

```bash
python scripts/bootstrap_promo_project.py \
  --workspace <output-dir> \
  --screenshots <screenshot-dir> \
  --layout-style swiss \
  --project-name "Acme" \
  --tagline "Close work faster"
```

Custom full-layout storyboard:

```bash
python scripts/bootstrap_promo_project.py \
  --workspace <output-dir> \
  --screenshots <screenshot-dir> \
  --storyboard storyboard.json
```

Content-grounded copy and narration scaffold:

```bash
python scripts/bootstrap_promo_project.py \
  --workspace <output-dir> \
  --screenshots <screenshot-dir> \
  --layout-style swiss \
  --brief-file project-article.md \
  --scenario "skill promo video" \
  --copy-language zh
```

Fine-grained DOM animation:

```bash
python scripts/bootstrap_promo_project.py \
  --workspace <output-dir> \
  --screenshots <screenshot-dir> \
  --motion-detail glyph
```

PNG fallback render mode:

```bash
python scripts/bootstrap_promo_project.py \
  --workspace <output-dir> \
  --screenshots <screenshot-dir> \
  --render-mode slides
```

Render the video from the generated workspace:

```bash
npm install
npm run render
```

Generate narration, keeping the original audio workflow:

```bash
python scripts/generate_voiceover_edge.py --workspace <output-dir>
```

## QA

Check these artifacts before rendering:

- `public/ppt/index.html`: the generated PPT deck.
- `public/slides/render-manifest.json`: rendered slide metadata.
- `src/promo-data.ts`: Remotion slide manifest, `pptScenes[].html`, render mode, and BGM settings.
- `src/ppt-template.css`: CSS extracted from the selected PPT template.
- `public/audio/voiceover-script.json`: narration scene list.
- `public/audio/motion-timeline.json`: measured scene and beat timing after TTS.

For Swiss decks, also run the PPT validator against `public/ppt/index.html`:

```bash
node <guizang-ppt-skill>/scripts/validate-swiss-deck.mjs public/ppt/index.html
```
